# Docker Compose 部署

OpenDeepWiki 在项目根目录只保留一份 `compose.yaml`。默认启动三个服务：PostgreSQL、后端 API 和前端 web 应用。

## 服务架构

| 服务 | 端口 | 描述 |
|---|---|---|
| `postgres` | `5432` | PostgreSQL 数据库 |
| `opendeepwiki` | `8080` | 带有 AI 处理的 ASP.NET Core 后端 API |
| `web` | `3000` | Next.js 前端应用 |

`opendeepwiki` 会等待 PostgreSQL 健康检查通过后启动；`web` 会等待后端健康检查通过后启动。

## 快速启动

```bash
git clone https://github.com/AIDotNet/OpenDeepWiki.git
cd OpenDeepWiki

# 按需在 compose.yaml 或环境变量中配置 AI Key
docker compose up -d --build
```

在 `http://localhost:3000` 访问应用。

## 常用配置

### 端口

| 变量 | 默认值 | 描述 |
|---|---|---|
| `OPENDEEPWIKI_WEB_PORT` | `3000` | 前端端口 |
| `OPENDEEPWIKI_API_PORT` | `8080` | 后端端口 |
| `POSTGRES_PORT` | `5432` | PostgreSQL 暴露端口 |

示例：

```bash
OPENDEEPWIKI_WEB_PORT=3001 docker compose up -d --build
```

### PostgreSQL

| 变量 | 默认值 |
|---|---|
| `POSTGRES_DB` | `opendeepwiki` |
| `POSTGRES_USER` | `postgres` |
| `POSTGRES_PASSWORD` | `opendeepwiki123` |

后端默认使用容器内 PostgreSQL：

```yaml
- Database__Type=postgresql
- ConnectionStrings__Default=Host=postgres;Port=5432;Database=${POSTGRES_DB:-opendeepwiki};Username=${POSTGRES_USER:-postgres};Password=${POSTGRES_PASSWORD:-opendeepwiki123}
```

### AI 提供商

至少配置聊天和 Wiki 生成所需的 API Key：

```yaml
- CHAT_API_KEY=${CHAT_API_KEY:-}
- CHAT_MODEL=${CHAT_MODEL:-gpt-4o}
- ENDPOINT=${ENDPOINT:-https://api.openai.com/v1}
- CHAT_REQUEST_TYPE=${CHAT_REQUEST_TYPE:-OpenAI}

- WIKI_CATALOG_API_KEY=${WIKI_CATALOG_API_KEY:-}
- WIKI_CONTENT_API_KEY=${WIKI_CONTENT_API_KEY:-}
```

如果目录生成和内容生成使用同一个提供商，也可以把 `WIKI_CATALOG_API_KEY`、`WIKI_CONTENT_API_KEY` 配成同一个值。

<Callout type="warn">
  正式环境请修改 `JWT_SECRET_KEY` 和 `POSTGRES_PASSWORD`。默认值只适合本地启动。
</Callout>

## 数据持久化

`compose.yaml` 使用两个 Docker 命名卷：

| 卷 | 用途 |
|---|---|
| `opendeepwiki-data` | 克隆仓库、生成文档、Graphify 产物 |
| `postgres-data` | PostgreSQL 数据 |

查看卷：

```bash
docker volume ls
```

## 构建镜像

```bash
docker compose build
docker compose build opendeepwiki
docker compose build web
```

如果已安装 `make`：

```bash
make build
make up
```

## 常见操作

```bash
docker compose up -d --build
docker compose logs -f
docker compose logs -f opendeepwiki
docker compose restart
docker compose down
```

## 故障排除

### 后端启动失败

- 验证 AI API Key 有效且端点可达
- 检查 PostgreSQL 容器是否健康：`docker compose ps`
- 查看日志：`docker compose logs opendeepwiki`

### 前端显示连接错误

- 确保后端健康检查通过：`docker compose ps`
- `API_PROXY_URL` 必须指向后端容器：`http://opendeepwiki:8080`

### 磁盘空间不足

- 克隆的仓库存储在 `opendeepwiki-data` 卷中。通过 web UI 或 API 清理旧仓库
- PostgreSQL 数据存储在 `postgres-data` 卷中，生产环境需要定期备份
